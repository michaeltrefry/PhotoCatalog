# Original XMP carrier extraction

`xmp_packets::inspect(path, &Limits)` and `inspect_sidecar(path, &Limits)` read selected regular files without pixel decoding or source writes. Sidecar selection, XML/RDF parsing, projections, conflict policy, and export are separate responsibilities. This module makes no claim that opaque bytes are valid XML.

The public `Inspection` records a BLAKE3 source revision, status, issues, retained `Packet`s, and separate `ParseInput`s. A packet's bytes and digest describe the exact payload at its absolute source ranges. JPEG APP1 payloads include their namespace and fragment headers. PNG iTXt payloads include their headers and original compressed bytes. TIFF values, Photoshop resources, WebP chunks, UUID payloads, sidecars, and individual AVIF item extents retain their original bytes. Nothing overwrites these bytes with normalized or reconstructed XML.

Parse inputs reference their source packet indices and explicitly label identity, header removal, decompression, or reconstruction. Extended JPEG input validates declared offsets, complete coverage, lengths, and MD5; its GUID identifies the extension group. Main packets remain separate. The RDF layer must resolve `xmpNote:HasExtendedXMP` against the extension GUID; this layer does not guess relationships from marker adjacency or merge main/extension RDF. AVIF provenance includes item ID, extent ordinal, construction method, content encoding, raw item-name hex, and all `cdsc` destination IDs, including orphan metadata items.

| Container | Retained carriers / traversal |
|---|---|
| JPEG | Every matching main and extended APP1, including duplicate main packets and metadata after entropy-coded scans. Stuffing and restart markers are handled structurally. |
| TIFF / DNG / CR2 / NEF / ARW / ORF / PEF / RW2 | Tag 700 in classic and BigTIFF directories, next-IFD chains, SubIFDs, Exif/GPS/interoperability IFDs. TIFF, ORF, and RW2 signatures are recognized; directory sharing is distinguished from cycles. |
| RAF | Declared embedded JPEG segment. Proprietary RAF metadata outside this segment has no implemented standardized XMP carrier; inspection reports this limitation explicitly. Selected sidecars remain fully supported. |
| PNG | Every iTXt with the exact `XML:com.adobe.xmp` keyword, with CRC validation and bounded zlib decompression. Other keywords are not treated as XMP. |
| PSD | Every standard `8BIM` resource ID 1060 in the version-1 image resource section, including duplicates and Pascal-name padding. Known private `AgHg` blocks use the same bounded framing and are skipped; their numeric IDs are not interpreted as standard XMP. PSB is explicitly unsupported, consistent with the image pipeline. |
| WebP | Every `XMP ` RIFF chunk, with declared boundaries and word padding. |
| AVIF | Every MIME `application/rdf+xml` item in each meta box, including multiple extents/items and `cdsc` references. `iloc` versions 0–2, `infe` 2/3, file offsets and idat offsets are supported. UUID XMP payloads are also retained. |
| CR3 | Standard XMP UUID payloads in BMFF boxes and known container hierarchies. Canon proprietary payloads are not scanned for XML byte patterns. |
| BMP | No evidenced standardized embedded carrier is implemented. Explicit `Unsupported` result; selected sidecars are retained verbatim. |

AVIF protected/external-reference items, item-offset construction method 2, zero-length extents, legacy infe 0/1, and unknown content encodings produce explicit limitations, never an absent result. Unknown encodings retain resolvable source extents. Gzip-encoded item parse input and PNG zlib parse input are derived bytes. No network/external-reference resolution occurs. Supported coverage is structural container metadata, not arbitrary XML signatures inside pixel or proprietary data.

Malformed containers retain carriers already recovered and report issues. BMFF framing preserves the validated prefix when a later sibling is malformed, including nested metadata boxes. Carrier reads and FullBox prefixes are bounded by their declared parent, so bytes in a following section cannot become valid XML input. Recognizable truncated JPEG/PNG/TIFF/PSD/WebP payloads retain available bytes with `incomplete` and declared-length provenance; they do not produce validated parse inputs. Invalid extended JPEG groups preserve individual fragments and suppress reconstruction. A resource limit is an incomplete inspection, not successful absence. `Absent` means a supported container was inspected without detected errors and contained no matching carrier; it does not certify image decodability.

Default limits: source 16 GiB; individual payload/reconstruction 16 MiB; total retained carriers 64 MiB; total parse inputs 64 MiB; cumulative metadata reads 128 MiB; 100,000 structural entries; 1,024 packets; nesting 32. Reads use checked source/parent bounds. Pixel segments are skipped by offset where possible; JPEG entropy marker traversal and full revision hashes use fixed 64 KiB buffers. Each revision hash reads at most the initially declared file length plus one byte, so source growth cannot prolong hashing indefinitely.

Non-regular files and source symlinks are rejected before opening and checked again after extraction. Unix opens use O_NOFOLLOW and O_NONBLOCK, then verify regular-file handle type and inode/device identity against the initial directory entry before reading; a raced FIFO cannot block and a raced symlink is not followed. Windows opens use FILE_FLAG_OPEN_REPARSE_POINT and reject a non-regular/reparse handle. Every in-limit source receives a whole-file digest. Qualified local APFS held-object/change-stamp verification and Windows deny-write/full-file-ID verification permit one hash pass; other cases retain conservative rehashing. Held and final pathname identities, length, and relevant timestamps are checked as described in [XMP source stability](XMP_SOURCE_STABILITY.md). A detected change yields `SourceChanged` and uncommittable revision evidence. This detects ordinary concurrent changes/replacements; it does not promise an atomic filesystem snapshot against a writer that deliberately changes and restores bytes between reads. Initial/open/final-path I/O errors are returned; metadata-read failures appear as explicit malformed inspection issues. Callers must not silently translate either to absence.

Tests construct public-safe metadata containers programmatically; they are not claims of pixel-decodable images or private-camera coverage. They check exact carrier ranges/digests, duplicates, encodings, reconstruction failures, compression limits, directory cycles/overflow, BMFF associations/extents, truncation prefixes, source and directory preservation, and bounded revision hashing.

PSD `AgHg` compatibility is corroborated by the [psd-tools image-resource reader](https://psd-tools.readthedocs.io/en/latest/_modules/psd_tools/psd/image_resources.html), which recognizes this alternate signature. Adobe's public specification documents standard `8BIM` framing; this compatibility support does not assign semantics to private payloads or admit arbitrary signatures. Name, size, payload padding, parent bounds and structural limits remain enforced.

References: [Adobe JPEG handler](https://raw.githubusercontent.com/adobe/XMP-Toolkit-SDK/7093513bd3caaad29da01db0f275d88a39d6bcc2/XMPFiles/source/FileHandlers/JPEG_Handler.cpp) defines main/extension carrier layout; [PNG iTXt specification](https://www.w3.org/TR/png-3/#11iTXt) defines headers/compression; [WebP RIFF specification](https://developers.google.com/speed/webp/docs/riff_container) defines metadata chunks; [libavif 1.3.0 item parser](https://raw.githubusercontent.com/AOMediaCodec/libavif/v1.3.0/src/read.c) documents supported item location/info/reference structure; [Adobe Photoshop file format](https://www.adobe.com/devnet-apps/photoshop/fileformatashtml/) identifies XMP resource 1060. The implementation does not use image 0.25.9's single-packet convenience hooks as complete extraction evidence.
