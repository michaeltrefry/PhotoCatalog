# Preview experiment protocol 1

Status: frozen candidate design; implementation and independent review precede execution. No timing result or selected default is implied. S6/sc-22841 owns this experiment. The existing interaction contract in IMPLEMENTATION_PLAN.md remains unchanged.

## Inputs and display preparation

The private input manifest contains the 22 independently validated S3 originals, the two validated CC0 Canon/Panasonic RAW files, and six deterministic preparation fixtures. A preflight must reject missing inputs, changed digests, duplicate identities and incorrect expected dimensions. Freeze all 30 IDs, source hashes, reference dimensions, camera/format groups, and quality crop rectangles before encoding. Private source paths and photos never enter Git. References are immutable and outputs are exclusively created in a new private directory.

Use `decode_full` for all originals, including CR2: no embedded-JPEG reference. The shared production API `preview::prepare` preserves S3's exact order: oriented linear-sRGB straight-alpha source; composite onto white in linear light; sRGB transfer; clamp to [0,1]; round to RGB8; then the pinned image crate's existing thumbnail resampler. Do not move quantization or transfer after resize. Preserve aspect ratio, longest-edge bounds and no upscaling. Reject invalid dimensions/nonfinite components. The float editor surface is unchanged. Prepared RGB8 bytes and dimensions are the exact lossless comparison reference, retained with a digest; save tagged sRGB PNGs for inspection. These are SDR previews, not HDR display or Adobe-appearance claims.

The six procedural fixtures independently check: (1) sRGB transfer endpoints/breakpoint and negative/above-one clipping; (2) straight alpha 0/0.5/1 over white; (3) EXIF orientations 1–8 using an asymmetric labeled raster; (4) quantize-before-area-resize using integer-reduction blocks and an independent scalar oracle; (5) smooth/saturated gradient and colored one-pixel edges; (6) seeded fine detail/noise. Expected transfer/alpha values use an independent float64 scalar implementation, not the product helper; exact 8-bit bytes, dimensions and coordinate mapping are asserted. Integer-reduction resampling uses independently computed block averages. Noninteger photographic resampling remains the pinned helper, identified in receipts rather than falsely called an independent oracle.

## Fixed candidates and decoder paths

Longest edges: persistent-thumbnail candidates **256, 512**; evictable-large candidates **1600, 2560**. Every input uses all four sizes without upscaling. JPEG qualities **50,65,80**; WebP **50,65,80**; AVIF **45,60,75**. Thus 36 configurations/input, 1,080 outputs maximum. Quality scales are not equivalent across codecs. No automatic tuning, per-image quality selection or hidden retries.

- JPEG: pinned image 0.25.9 JpegEncoder, 4:4:4 component sampling (each H/V factor=1, from pinned encoder source), recorded and validated from SOF; decode through the same pinned image JPEG decoder used by production preview reads, materialize RGB8. Do not switch to system libjpeg during measurement.
- WebP: native libwebp lossy, WEBP_PRESET_DEFAULT, method=4, thread_level=0, lossless=0; all other initialized fields retained and version identified. Decode through pinned image 0.25.9/image-webp 0.2.4 to RGB8. Lossy WebP uses YUV420; original metadata/alpha are absent because preparation is opaque sRGB.
- AVIF: libavif with explicitly available AOM encoding and decoding, quality as above, speed=6, maxThreads=1, autoTiling=false, zero tile rows/columns, depth=8, YUV420, full range, BT709 primaries/matrix and sRGB transfer. RGB conversion disables libyuv and fixes average downsampling/bilinear upsampling. Single still image, no transform, gain map, alpha or source metadata. Decode through the shared production adapter to allocated, fully populated RGB8; reject mismatched cache color/depth/transform contracts. No AUTO codec fallback.

All containers encode already-oriented opaque sRGB. The preview manifest declares this contract; AVIF declares matching CICP. Raw EXIF/XMP is retained elsewhere, not copied into cache payloads. Record Cargo.lock, binary/source/runner hashes, OS/CPU/RAM/storage, renderer/preparation version, libwebp/libavif/AOM versions and effective settings. Check AVIF capability before any measured attempt. Decoder timers begin with encoded bytes in memory and end only after RGB8 materialization, allocation and color conversion; file reads and checksums are separate intervals. Production must call these exact APIs.

## Stage A: codec and quality evidence

Prepare originals serially once, recording full-original decode and preparation separately. One codec worker and one native thread; no builds, foreign render work or competing benchmark during the coordinator's reserved lane. For every candidate: one encode warmup then **3 encodes**; three decode warmups then **20 decodes**. Retain all raw times, failures, dimensions, pixels/digests, container bytes, CPU time and peak RSS. Preserve outputs/digests from all encodes to expose nondeterminism. Three encode samples support median/range only; 20 decode samples give exploratory interpolated p95/p99, not a robust extreme-tail guarantee. No timeout or failed codec gets an invented passing sample.

Compute RGB8-domain MSE/PSNR against the exact prepared bytes. SSIM is the mean of per-channel, nonoverlapping 8x8 blocks (partial boundary blocks included), population variance/covariance, C1=(0.01*255)^2, C2=(0.03*255)^2; report this explicitly as block RGB SSIM, not MS-SSIM or another standard implementation. Metrics are descriptive; no new numeric quality pass threshold. Independently test identical/constant/error cases before using the implementation.

Generate private lossless PNG contact sheets, 100% crop pairs, toggles and amplified differences. Freeze crop positions at center plus four quadrants, each a quarter of image width/height, before viewing encoded results. Blind labels through a seeded manifest permutation, retaining the reverse mapping separately. Inspect all candidates at intended display size and fixed crops using the same rubric: blocking, ringing, chroma bleeding, missing texture, banding, color and alpha errors. Include worst files and synthetic fixtures, not only attractive examples. Record reviewer decisions for each candidate/tier.

Report each image and format group, bytes median/p95/max and corpus sum, encode median/range, decode n/p50/p95/p99/max, RSS and errors. Project corpus mean bytes/asset to 1M/5M/10M with a clear compatibility-corpus sampling limitation. Do not claim these 30 inputs represent the user's library frequency distribution. Select one thumbnail and one larger configuration from visually acceptable candidates using measured footprint and decode cost; no per-query or per-camera settings. If none is acceptable, publish the failed matrix and explicitly revise the protocol before another run.

## Stage B: retained storage and interaction

After reviewed Stage A selection, freeze the selected pair in a new configuration receipt before Stage B. Compare flat files against two-level hash-prefix directories at **10,000 and 100,000 genuinely distinct entries**. Payload reuse is permitted but must not collapse through content-hash deduplication: use distinct synthetic logical request keys and report distinct directory-entry counts independently of payload digests. Include manifest/index/directory/allocation overhead, logical bytes, allocated bytes, file count and partial-publication recovery. Three fixed sequential and three seeded random full lookup passes per layout/count; first pass separately labeled; subsequent OS cache uncontrolled/warm. All reads include checksum verification and use identical lookup sequences. Do not extrapolate timing to a million filesystem entries.

The headless retained first-page workload is **200 visible thumbnail identities**, IDs 0..199, mapped round-robin onto all 30 prepared fixtures but stored under distinct revision keys. Reuse/dedup and source-image diversity are explicitly reported. All thumbnails are retained before each trial; originals are disconnected for offline trials. Use SQLite 256 MiB per connection, decoded-thumbnail LRU **256 MiB**, encoded staging **32 MiB**, queued request descriptors **400**, a single active preview decode worker, and no active full-original renderer for retained-page measurements. Existing ≤4 GiB browse RSS remains the admission gate, not merely the sum of requested budgets.

Run **100 warm page trials** (three warmups) and **20 fresh-process trials**. Warm trials retain the process/DB connection and OS cache but clear decoded LRU before each trial, so every trial includes thumbnail decode; report an additional hot-LRU observation separately. Fresh trials start a new process with empty decoded/encoded caches; OS caches are not evicted. Timer starts before DB page lookup and ends with all 200 RGB8 thumbnails available. Separately record DB time, read/checksum, decode, queue delay and total wall time (do not sum overlapping intervals). Compare the total warm headless cost with the existing 1-second first-visible-page target; UI time is explicitly unavailable until S12 and no complete UI pass is awarded here.

Fixed navigation trace: 100 viewports, 200 IDs each, starting at ID0 then advancing by50 modulo10,000; replace the viewport every50ms, cancel prior out-of-view consumers; final viewport awaits completion. Repeat10 times. Record request/admission/completion order, stale/canceled publication attempts, queue peaks, dropped/superseded requests, decoded-cache hits/misses and time to final visible completion. Do not infer 60Hz frame time from this headless trace.

Constrained configuration repeats first-page/navigation with decoded LRU **32 MiB**, staging **8 MiB**, queue **200**, and one decoder; keep the existing DB profile. Report misses, retained-output memory, peak RSS and errors. Retained returned pixels count toward process RSS even if evicted from LRU. All output buffers have explicit ownership/release; callers retaining unlimited pages are not a valid bounded browse configuration.

Larger-cache test quota **64 MiB**, thumbnail retained quota **128 MiB** on a disposable fixture catalog. Test quota saturation, exact byte accounting including pending publications, reads racing eviction, source disconnection and disk-exhaustion injection. Retained thumbnails are not silently evicted to admit large previews. If retained storage is full, retain prior valid data and report inability to admit new thumbnails. Production quotas/locations remain configurable; these small quotas are test configurations, not product defaults.

For full-original background work, first record isolated per-fixture complete-worker peak RSS, including native allocations, float buffers, preparation and encoding. Freeze the worker reservation from the maximum plus documented accounting margin before admitting concurrency. Begin with one original-render worker; a two-worker diagnostic is allowed only if reservations fit the explicit worker-memory allowance. Browse RSS and renderer peaks are separately reported. Freeze the allowance before that diagnostic; insufficient room results in queued work, not a relaxed budget.

## Correctness and publication gates

Verify asset/edit/render revisions in every request and conditional catalog attachment. Queue saturation, duplicate consumers, foreground promotion and cancel-before-start are deterministic tests. Exercise cancellation during native decode/encode, then measure actual resource-release latency: suppressing callbacks alone does not prove running work stopped. Retain native-library limits and worker/process boundaries in the evidence.

Inject source changes, rapid edit revisions, same-key concurrent completion, low disk, read/eviction races, and process death before/after file sync, publication and database attachment. A stale result may become an unreferenced immutable artifact but must never replace the current revision. Recovery removes abandoned temporary/unreferenced files safely and preserves the last valid offline thumbnail. No failed/partial file is presented as valid, no original is modified and no schema migration discards existing data.

The coordinator reserves the quiet lane only after protocol, adapters, fixture oracles and harness have passed independent review. Every campaign output is new/exclusive, retains failures and exact settings, and records UTC/monotonic boundaries and competing-load telemetry. Review evidence once before choosing defaults; no best-of retries. S6 remains incomplete until configurable storage, resource limits, priority/cancellation, stale-key protection and recovery all work through production APIs. Desktop rendering/frame-time validation belongs to S12; it cannot be substituted with this experiment.

## Adapter/build review and execution interface

The first implementation commit provides the shared codec/preparation APIs, procedural fixture generator, Stage A coordinator, receipt validation and blinded quality artifacts. Stage B storage/scheduling and main-catalog integration remain required S6 work; their presence in this protocol is not an implementation claim. No default codec is selected by the adapter commit.

Native dependencies add libwebp (minimum1.2, observed local1.6.0); macOS package `webp`, Ubuntu package `libwebp-dev`, Windows vcpkg port `libwebp`. libavif/AOM is already provisioned; require its actual encode/decode capability rather than assuming package presence. The AVIF fields used are available in libavif1.0.4 as well as1.4.2. Keep the project's existing decoder libraries and licenses; libwebp's BSD notice is retained in `third-party/libwebp-LICENSE.txt` and must accompany distributed binaries. Primary API references: [image0.25.9 JPEG encoder source](https://github.com/image-rs/image/blob/v0.25.9/src/codecs/jpeg/encoder.rs), [image0.25.9 WebP API](https://docs.rs/image/0.25.9/image/codecs/webp/struct.WebPEncoder.html), [libwebp1.6 encoder API](https://github.com/webmproject/libwebp/blob/v1.6.0/src/webp/encode.h), [libavif1.0.4 API](https://github.com/AOMediaCodec/libavif/blob/v1.0.4/include/avif/avif.h).

Before timing, review a concrete private manifest with exactly22 `private`,2 `public` and6 `preparation` entries, each with `id,path,sha256,width,height,kind,group`; preparation entries additionally contain four independent oracle paths/digests/dimensions. `scripts/generate_preview_fixtures.py NEW_DIRECTORY` creates only the six procedural fixtures/oracles; compose their manifest with the previously validated originals without copying photos into Git. `preview_probe versions` reports compiled source/Cargo-lock identities and native codec capabilities. `scripts/preview_experiment.py --manifest MANIFEST --binary RELEASE_PROBE --output NEW_DIRECTORY --lane-token coordinator-authorized` is executed only after the coordinator actually grants the lane; the string is an accidental-execution guard, not an authorization system.

The main catalog owns `assets.render_generation`, monotonically incremented in import reserve/retry and metadata/edit transactions. Preview-manifest desired/current revisions cannot reverse-register an older catalog generation. Reads validate the current catalog identity; cross-store interrupted updates reconcile on startup without discarding valid retained thumbnails solely because stores temporarily disagree. An older retained fallback must be explicitly labeled, never reported as the current edit rendering.

The pre-execution review repair binds each Stage A artifact chain explicitly. An untimed `verify-case` subprocess rehashes all three encoded files, decodes those saved bytes through the production adapter, checks prepared RGB/PNG equality and decoded PNG equality, and recomputes quality. The coordinator requires that verification before admitting a candidate to blinded review; the review manifest carries expected reference/candidate pixel digests. Review output files are re-read and hashed, and their receipt plus separate mapping receive independent SHA-256 identities. These verification and quality subprocesses are excluded from codec timing samples. A later codec/write/quality failure retains completed timing samples, artifact identities, phase and iteration in the failed receipt; failures are never retried as replacement samples. Source preservation is part of the `complete` predicate.

AOM encoder/decoder capability is an actual preflight gate before preparing or measuring inputs. The campaign records OS release, architecture, CPU model availability, RAM, output/input filesystem and capacity information without hardware serials. The existing reviewed `benchmarks/observe_host.py` sampler runs in a passive thread with one-second cadence; its first real sample is persisted before the first preparation child. UTC/monotonic CPU/RAM/swap/disk/process-basename/AGX observations continue through codec and untimed verification children. `host.jsonl` and its final receipt are exclusively created and source/data hashed into campaign evidence. Missing GPU or other counters remain explicitly unavailable, never idle; successful telemetry collection does not award quiet-host admission. The coordinator independently reviews competing load before accepting performance evidence. No observer launches/stops foreign workloads or changes performance budgets.

Quality receipt reconciliation allows only decimal JSON roundtrip error: each finite MSE/PSNR/SSIM value must differ by no more than `4 * f64::EPSILON * max(1, abs(actual), abs(reported))`. Identical flags, maximum integer channel error and nullable PSNR remain exact. This is a serialization allowance, not a quality acceptance threshold. A nonuniform 9x11 three-codec regression reproduces the default JSON parser's one-ULP mismatch, then verifies valid receipts pass and a changed metric fails.
