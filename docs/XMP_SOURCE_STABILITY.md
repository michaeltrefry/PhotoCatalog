# XMP source stability and read cost

`inspect` and `inspect_sidecar` still identify every in-limit source by its whole-file BLAKE3 digest. Raw packet bytes, transformed parse inputs, status precedence and metadata/retention limits are unchanged. Unsupported formats and sources without XMP still receive the complete digest; inputs exceeding the source limit retain the explicit ResourceLimit result without a digest.

On Unix, inspection holds the opened regular file and compares its device/inode, length, modification time and precise filesystem change time before hashing, after hashing and after parsing. A final no-follow pathname open must identify the same unchanged held object. This relies on the filesystem updating ctime for writes, including writes whose mtime is restored. It is change detection, not an atomic snapshot or protection against a filesystem that falsifies its stamps.

On Windows, inspection attempts a read handle that shares reads and deletion but excludes writes, and retains it through hashing, parsing and final pathname verification using the full 128-bit file ID. Microsoft documents that omitting FILE_SHARE_WRITE also conflicts with an existing writable mapping: https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew . Platform tests cover both a writer handle and a mapping whose creator handle was closed. A pathname replacement remains detectable even though the lease allows rename/delete.

If the lease or required identity/stamp proof is unavailable, inspection conservatively retains the prior full rehash verification: two digest passes on Unix, and up to three on other platforms including a pathname digest. Detected stamp mismatches remain SourceChanged even if a later fallback digest matches. SourceChanged packets are retained as uncommitted evidence, never eligible for semantic projection. Opening a replaced nonregular/symlink source fails safely.

`inspect_with_work` and `inspect_sidecar_with_work` additionally return ReadWork with the verification method, actual digest passes, bytes returned to hashing, and bytes returned to the bounded parser. These are logical read counts, not device I/O, elapsed-time or memory measurements. The ordinary Inspection serialization and SourceRevision contract are unchanged. No cross-call cache or mtime-only reuse is introduced.

Focused fixtures compare optimized and conservative results exactly, exercise restored-mtime and transient rewrites at two checkpoints, retained-object pathname replacement, post-fallback replacement, and 8 MiB payloads with small/absent XMP. Windows-only sharing/mapping cases require Windows CI; Unix results do not qualify those platform behaviors.
